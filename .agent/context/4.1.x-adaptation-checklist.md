# 4.1.x 分支适配指南

> 从 master（3.5.x）cherry-pick 代码到 4.1.x 分支时，需要做以下**升级适配**。
> 4.1.x = Spring Boot 4.1.x + Spring Framework 7 + JDK 17（jakarta 不变）

---

## 0. 分支定位与通用原则

### 0.1 两条分支的关系

| | master | 4.1.x |
|---|---|---|
| 版本线 | Spring Boot **3.5.x** | Spring Boot **4.1.x**（兼容 4.0） |
| 定位 | 主线、最新稳定 | 下游适配分支（同 `master → 2.7.x` 的模式） |
| 兼容层 | **无** | 有（SB4/Spring 7 适配代码） |
| 同步方向 | 变更源头 | 接收方（cherry-pick） |

**master 是完全干净的 3.5.x 代码**，不含任何 Spring Boot 4 / Spring 7 兼容处理。
所有 4.x 适配代码**只存在于 4.1.x 分支**。

### 0.2 同步流程

```
□ 0. 在 master 上完成功能开发并通过全量测试
□ 1. 切到 4.1.x，cherry-pick master 的提交
□ 2. 按本指南逐项做 4.x 适配（下方章节）
□ 3. mvn -Pspring-boot-4.1 clean test 直到全绿
□ 4. 提交
```

### 0.3 绝不 backport 到 master 的内容

以下内容**只属于 4.1.x**，不得出现在 master：

- `spring-boot-starter-web/.../Boot4WebServerInitializedEventAutoConfiguration.java`
- `spring-boot-starter-web/.../support/Boot4WebServerInitializedEventBridge.java`
- `spring-web-examples/spring-web-example-support-test`（TestRestTemplate shim 模块）
- 任何 `spring-boot-4.0` / `spring-boot-4.1` Maven profile

### 0.4 版本号规则

- 分支的 `project.version` 在**开发期沿用主线**（当前为 `3.5.6`）；主线之后的版本提升**不会自动同步**到本分支，属正常；
- **发布本分支时统一提升为对应的 4.1.z** —— 首个 4.1.x 发布版本号定为 **`4.1.7`**（发布前把全仓 `project.version` 一次改到位）；
- 与 `spring-boot.version` 无关：`spring-boot-4.1` profile 里的 `4.1.0` 指 **Boot** 版本，不随项目版本号变；
- 本分支当前**尚无发布版本**（仓库中没有任何 4.x tag）。

## 1. POM 与 profile

### 1.1 根 pom

4.1.x 在根 `pom.xml` 的 `<profiles>` 中**额外**保留：

```xml
<profile>
    <id>spring-boot-4.0</id>
    <properties>
        <spring-boot.version>4.0.7</spring-boot.version>
        <jackson.version>2.21.4</jackson.version>
        <jackson-annotations.version>2.21</jackson-annotations.version>
    </properties>
</profile>
<profile>
    <id>spring-boot-4.1</id>
    <properties>
        <spring-boot.version>4.1.0</spring-boot.version>
        <jackson.version>2.21.4</jackson.version>
        <jackson-annotations.version>2.21</jackson-annotations.version>
    </properties>
</profile>
```

> profile id 与 master 的 `spring-boot-4.x` 同名，`-Pspring-boot-4.1` 会按 id 激活到所有子模块。

### 1.2 新增 artifact 的 profile 内声明

Boot 4 拆出的 artifact 在 **Boot 3.x BOM 里没有版本**，故**只能在 `spring-boot-4.x` profile 内**条件引入：

| 模块 | 需要补的 artifact |
|---|---|
| `spring-boot-starter-web` | `spring-boot-web-server`（`WebServer` / `ServerProperties` 拆分） |
| `spring-web-examples/spring-web-example-support-test` | `spring-boot-resttestclient`、`spring-boot-restclient` |
| `spring-web-benchmark` | `spring-web`、`spring-boot-web-server`、`jackson-databind`（`starter-json` 不再传递） |

### 1.3 编译期排除

`spring-boot-starter-web` 的 SB4 profile 内需排除仅 SB3 可用的自动配置类
（profile 内的 `maven-compiler-plugin` 配置是**替换**而非合并根配置，需完整重写）：

- `SpringWebRuntimeHints`
- `WebServerInitializedEventAutoConfiguration`
- `support/PerfWebServerInitializedEvent`

**被排除编译的类，其引用方也必须一起排除**，否则 javac 会因 import 把被排除的文件重新拉进来。

| master（Boot 3.5） | 4.1.x（Boot 4） |
|---|---|

| `org.springframework.boot.test.web.client.TestRestTemplate` | `org.springframework.boot.resttestclient.TestRestTemplate` |
| `org.springframework.boot.web.client.RestTemplateBuilder` | `org.springframework.boot.restclient.RestTemplateBuilder` |

## 3. API 变更

### 3.1 `HttpHeaders` 不再是 `MultiValueMap`

Spring 7 的 `HttpHeaders` **不再实现** `MultiValueMap`，相关方法整体移除：

| master（3.5） | 4.1.x 需要的处理 |
|---|---|
| `headers.keySet()` / `containsKey()` / `entrySet()` / `values()` / `get(Object)` / `remove(Object)` | 由 `WebHttpHeaders` 兼容层承载（`asMultiValueMap()` 或 MethodHandle `findSpecial` 调父类） |
| `super.xxx()` 直调 | 编译期不可用（Spring 7 父类无此方法）→ 走 MethodHandle |

**这一项是 4.1.x 最大的适配面**，集中在 `spring-web/src/main/java/io/springperf/web/http/WebHttpHeaders.java`。

> ⚠️ master 上的 `WebHttpHeaders` 已是纯 3.5 增强（Content-Type 缓存 + Netty 常量名直通），
> **4.1.x 需要在它之上重新叠加版本兼容分支**。cherry-pick 该文件时须特别注意。

### 3.2 已移除的 API

| master（存在） | 4.1.x |
|---|---|
| `ResponseEntity.getStatusCodeValue()` | 已移除 → `getStatusCode().value()`（**master 也建议用后者**） |
| `org.springframework.util.concurrent.ListenableFuture` | 已移除 → 反射/代理适配（见 `ListenableFutureAdapter`） |
| `ResponseStatusException.getResponseHeaders()` | 已移除 → `getHeaders()` |
| Spring Security `authorizeRequests` / `.and()` | 已移除 → `authorizeHttpRequests` + `httpBasic(Customizer.withDefaults())` |

### 3.3 同名方法语义变更（最易漏）

| API | 差异 |
|---|---|
| `HttpHeaders.putAll(HttpHeaders)` | Boot 4 新增该重载，**语义为整体替换**（非 Map.putAll 的追加）；且 `put` 落到只读视图会抛异常 → 改为逐条 `add`（或复用 master 侧的 `WebHttpHeaders`） |
| `RestTemplateBuilder` 超时 | `setConnectTimeout` / `setReadTimeout` → `connectTimeout` / `readTimeout` |
| `TestRestTemplate` 构造 | 无参构造由 `TestRestTemplate(HttpClientOption...)` 承担 |

## 4. 依赖图变化（Boot 4 的 starter 精简）

| starter | Boot 3.5 传递 | Boot 4 |
|---|---|---|
| `spring-boot-starter-json` | `spring-web`、Jackson 2 `databind` | **均不再传递**（改用 Jackson 3） |

> 依赖 web 注解（`@RestController`）却只靠 `starter-json` 的模块会**编译失败**，需显式补 `spring-web`。

## 5. 测试适配

### 5.1 TestRestTemplate 的统一入口

`TestRestTemplate` / `RestTemplateBuilder` 包名跨版本不同，**无法用同一份 import**。
4.1.x 通过 `spring-web-example-support-test` 模块提供 shim：

- `src/main/sb3/java` 与 `src/main/sb4/java` 各放一份**同名同包**的薄封装
- 由 profile 经 `build-helper-maven-plugin:add-source` **二选一**挂载
- examples 的 E2E 测试统一 `import io.springperf.example.support.TestRestTemplate`

> **依赖必须标 `<optional>true</optional>`**：否则 `spring-boot-test` 会经 test-scope
> 把一套 junit 版本传递到下游，与下游自身 `starter-test` 冲突，
> surefire 报 `TestEngine with ID 'junit-jupiter' failed to discover tests`。
> 该 shim 模块无测试，须设 `<skipTests>true</skipTests>`。

### 5.2 按条件跳过的用例

| 场景 | 处理 |
|---|---|
| `ListenableFuture`（Spring 7 已移除） | `assumeTrue(ListenableFutureAdapter.isAvailable(), ...)` |
| 其他版本专属 API | 参照 `VirtualThreadE2ETest` 的 `assumeTrue` 模式 |

## 6. 检查清单

```
□ 1. 根 pom 是否保留 spring-boot-4.0 / 4.1 profile？
□ 2. 需要的 Boot 4 新 artifact 是否已在 profile 内条件引入？
□ 3. spring-boot-starter-web 的 compiler excludes 是否覆盖了 SB3-only 类及其引用方？
□ 4. HttpHeaders 相关调用是否全部走兼容层（不得直接 keySet/containsKey）？
□ 5. 是否使用了已移除 API（getStatusCodeValue / ListenableFuture 直用 / getResponseHeaders）？
□ 6. putAll(HttpHeaders) 是否已改为逐条 add（避免替换语义与只读异常）？
□ 7. 只依赖 starter-json 的模块是否补了 spring-web？
□ 8. examples 的 TestRestTemplate import 是否指向 shim？
□ 9. shim 模块依赖是否标了 optional、是否 skipTests？
□ 10. spring-boot-starter-web 的 AutoConfiguration.imports 是否与现存类一致？
□ 11. mvn -Pspring-boot-4.1 clean test 是否全绿？
```

## 7. 常见陷阱

- **切换 profile 后必须 `clean`**：4.x 编译会在 `target/classes` 留下按 Spring 7 签名编译的字节码，
  再跑 3.5 的测试（不 clean）会复用它们，报一串 `NoSuchMethodError`
  （如 `HttpEntity.<init>(Object, HttpHeaders)`），**看起来像代码回归、实则是脏 target**。
- **`AutoConfiguration.imports` 要同步**：删除自动配置类后若忘记删注册项，
  启动时报 `Unable to read meta-data for class ...`，整个 Spring 上下文起不来。
- **不可变 Builder 不能用继承做 shim**：`RestTemplateBuilder` 每个方法都 `return new ...`；
  继承覆写时 `super.rootUri()` 的返回值被丢弃，链式配置全丢
  （表现为运行期 `IllegalArgumentException: URI with undefined scheme`）。**用组合**。
- **profile 内的 plugin `configuration` 是替换而非合并**：在 profile 里只写 `<excludes>` 会丢掉根配置的其余部分。
