# 4.1.x 分支适配指南

> 从 master（3.5.x）cherry-pick 代码到 4.1.x 分支时，需要做以下**升级适配**。
> 4.1.x = Spring Boot 4.1.x + Spring Framework 7 + Jackson 3 + JDK 17（jakarta 不变）
>
> **本分支专用 Spring Boot 4**：默认构建即 4.1，不再保留 3.5.x 兼容路径。

---

## 0. 分支定位与通用原则

### 0.1 两条分支的关系

| | master | 4.1.x |
|---|---|---|
| 版本线 | Spring Boot **3.5.x** | Spring Boot **4.1.x**（`-Pspring-boot-4.0` 可切 4.0） |
| 定位 | 主线、最新稳定 | 下游适配分支（同 `master → 2.7.x` 的模式） |
| JSON 栈 | Jackson **2**（`com.fasterxml.jackson`） | Jackson **3**（`tools.jackson`）+ 注解 2.21 |
| 同步方向 | 变更源头 | 接收方（cherry-pick） |
| 构建 | `mvn clean test`（默认 3.5） | `mvn clean test`（**默认即 4.1**，无需 `-P`） |

**master 是完全干净的 3.5.x 代码**，不含任何 Spring Boot 4 / Spring 7 兼容处理。
所有 4.x 适配代码**只存在于 4.1.x 分支**。

**4.1.x 采用「专用写法」而非「兼容写法」**（与 `2.7.x` 分支一致）：不写运行时/编译期版本分支，
直接面向 Spring 7 / Jackson 3 的 API 实现。曾经的 `WebHttpHeaders` MethodHandle 版本桥接、
`Boot4WebServerInitializedEventBridge` 的 ASM 运行时字节码生成、`ResponseStatusExceptionAdapter`
的方法名反射探测等，均已随专用化移除。

### 0.2 同步流程

```
□ 0. 在 master 上完成功能开发并通过全量测试
□ 1. 切到 4.1.x，cherry-pick master 的提交
□ 2. 按本指南逐项做 4.x 适配（下方章节）
□ 3. mvn clean test 直到全绿（默认即 4.1）
□ 4. 提交
```

同步时若 master 的提交描述的是「master 视角」的事实（例如「兼容层已全部移除」），
在 4.1.x 上需按本分支立场改写——这类提交**不能照搬**。

### 0.3 绝不 backport 到 master 的内容

以下内容**只属于 4.1.x**，不得出现在 master：

- Jackson 3（`tools.jackson`）依赖与 import——master 用 Jackson 2
- Jackson 3 的 `FAIL_ON_NULL_FOR_PRIMITIVES` 兼容处理（`JacksonMappers.defaultMapper()`，见 §3.4）
- Netty 4.2 的版本走向——master 的 Boot 3.5 基线是 Netty **4.1**，不要反向同步（见 §4.1）
- `spring-web-examples/spring-web-example-support-test` 的 `src/main/sb4` 源码与相关依赖
- `StringHttpMessageConverter` 的注册与排序（见 §5.3）
- 转发头解析的自实现（`NettyServerHttpRequest` 的 host/port 与 `NettyHttpServletRequest` 的
  `getContextPath`，见 §4.2）——master 有 Servlet 容器，走 Boot 的 `ForwardedHeaderFilter`
- Spring AI 2.x（master 用 1.x，见 §4.3）
- 任何 `spring-boot-4.0` / `spring-boot-4.1` Maven profile

### 0.4 版本号与 changelog 规则（2026-10-08 起）

- **本分支独立发版，版本号走 `4.1.z`**：首个发布版本为 **`4.1.7`**；发布时把全仓 `project.version`
  一次改到位。分支的 pom 版本**不跟随主线**（此前"开发期沿用主线版本号"的旧规则作废）。
- **发布对齐**：`4.1.7` ≈ `3.5.7`，此后 `4.1.8` ≈ `3.5.8` ……（同一轮发布的内容基本相同，差异只在分支适配）。
- **changelog 三支趋同（长期目标）**：`master` / `2.7.x` / `4.1.x` 的 `CHANGELOG.md` 与
  `docs/en/changelog.md` **内容最终完全一致** —— 三个分支的全部发布节都要各自收录，每轮发布后互相同步补齐。
  因此本分支既要写自己的 `## [4.1.z]` 节，也要**原文收录** master 的 `## [3.5.z]` 节（反向同理）。
- **首个分支版本**（`4.1.7`）的说明里必须写明「自 master 拆分、独立发版」。
- 同步 master 的发布节时 `## [3.5.z]` 一律**原文照收**（保证三份逐字一致），不要按分支立场改写发布节。
- **版本号提升必须覆盖分支专属模块**：`4.1.x` 比 master 多出 `spring-web-examples/spring-web-example-support-test`
  （见 §0.3）。同步 master 的版本提交后，要**全仓重新扫描** pom 里的旧版本号（如 `<version>3.5.6</version>`）并一并提升，
  否则某个子模块的父版本与根 pom 不一致 → Maven 连工程都读不了（`The build could not read 1 project`），
  连带该 pom 里靠 BOM 管理版本的依赖也报 `dependency.version is missing`。
- **版本号一动就立刻验证**：提升后马上跑 `mvnw -q validate`（或受影响模块 `test-compile`），别等下一笔 cherry-pick 之后才发现。


## 1. POM 与 profile

### 1.1 根 pom

4.1.x 的 `spring-boot.version` **默认值直接写死为 4.1.0**（不靠 `activeByDefault` 的 profile）：

```xml
<spring-boot.version>4.1.0</spring-boot.version>
```

`<profiles>` 中只保留 `spring-boot-4.0`（切回 4.0.7）：

```xml
<profile>
    <id>spring-boot-4.0</id>
    <properties>
        <spring-boot.version>4.0.7</spring-boot.version>
    </properties>
</profile>
```

> Jackson 版本不再由本项目的属性覆盖——Boot 4 的 BOM 同时管理 Jackson 3（`tools.jackson`）
> 与注解用的 Jackson 2（`com.fasterxml.jackson.annotation`）。

### 1.2 Boot 4 拆出的 artifact

这些 artifact 直接进各模块的**主 `<dependencies>`**（不再放 profile）：

| 模块 | 需要补的 artifact |
|---|---|
| `spring-boot-starter-web` | `spring-boot-web-server`（`WebServer` / `ServerProperties` 拆分） |
| `spring-web` | `tools.jackson.core:jackson-databind` + `com.fasterxml.jackson.core:jackson-annotations` |
| `spring-web-examples/spring-web-example-support-test` | `spring-boot-resttestclient`、`spring-boot-restclient` |
| `spring-web-benchmark` | `spring-web`、`spring-boot-web-server`、`tools.jackson.core:jackson-databind`（`starter-json` 不再传递前两者） |

### 1.3 编译期排除

**已不再需要**。原 SB4 profile 通过 `maven-compiler-plugin` 的 `<excludes>` 排除三个 SB3 专属文件
（`SpringWebRuntimeHints`、`WebServerInitializedEventAutoConfiguration`、`support/PerfWebServerInitializedEvent`）。
专用化后这些文件已按 SB4 形态改写或删除，排除配置已移除。

## 3. API 变更


### 3.1 `HttpHeaders` 不再是 `MultiValueMap`

Spring 7 的 `HttpHeaders` **不再实现** `MultiValueMap`，相关方法整体移除：

| master（3.5） | 4.1.x 需要的处理 |
|---|---|
| `headers.keySet()` / `containsKey()` / `entrySet()` / `values()` / `get(Object)` / `remove(Object)` | 由 `WebHttpHeaders` 兼容层承载（`asMultiValueMap()` 或 MethodHandle `findSpecial` 调父类） |
| `super.xxx()` 直调 | 编译期不可用（Spring 7 父类无此方法）→ 走 MethodHandle |

**这一项是 4.1.x 最大的适配面**，集中在 `spring-web/src/main/java/io/springperf/web/http/WebHttpHeaders.java`。

> ⚠️ **禁用兼容写法**。master 与 4.1.x 各有一份**单一实现**：
> - master：`HttpHeaders` 在 Spring 6 下本身实现 `MultiValueMap`，故直接 `super.*`
> - 4.1.x：Spring 7 的 `HttpHeaders` 不再实现 `MultiValueMap`，父类没有的方法
>   （`containsKey` / `keySet` / `values` / `entrySet` 等）委派给 `asMultiValueMap()` 返回的视图
>
> 曾有过一版用 `static final` + `MethodHandle` 在类加载期区分 6.x/7.x 的实现，
> **专用化后已删除**——不要在 cherry-pick 时把它带回来。

### 3.2 已移除的 API

| master（存在） | 4.1.x |
|---|---|
| `ResponseEntity.getStatusCodeValue()` | 已移除 → `getStatusCode().value()`（**master 也建议用后者**） |
| `org.springframework.util.concurrent.ListenableFuture` | 已移除 → **框架已删除该返回类型的支持**（原实现是恒 false 的死代码） |
| `ResponseStatusException.getResponseHeaders()` | 已移除 → `getHeaders()`（**直接调用**，不再反射探测方法名） |
| Spring Security `authorizeRequests` / `.and()` | 已移除 → `authorizeHttpRequests` + `httpBasic(Customizer.withDefaults())` |

### 3.3 同名方法语义变更（最易漏）

| API | 差异 |
|---|---|
| `HttpHeaders.putAll(HttpHeaders)` | Boot 4 新增该重载，**语义为整体替换**（非 Map.putAll 的追加）；且 `put` 落到只读视图会抛异常 → 改为逐条 `add`（或复用 master 侧的 `WebHttpHeaders`） |
| `RestTemplateBuilder` 超时 | `setConnectTimeout` / `setReadTimeout` → `connectTimeout` / `readTimeout` |
| `TestRestTemplate` 构造 | 无参构造由 `TestRestTemplate(HttpClientOption...)` 承担 |

### 3.4 Jackson 3（`tools.jackson`）

Boot 4 / Spring 7 的 JSON 生态已迁到 Jackson 3，**与 master 的 Jackson 2 不是同一套**。
Spring 注入的 `ObjectMapper` 是 Jackson 3，框架的转换器必须对齐，否则二者互不相认。

| Jackson 2（master） | Jackson 3（4.1.x） |
|---|---|
| `com.fasterxml.jackson.databind.*` | `tools.jackson.databind.*` |
| **注解 `com.fasterxml.jackson.annotation.*`** | **不变**——`tools.jackson` 的 BOM 明确说明「annotations 没有 3.x 版本，用最新的 2.x 代替」，故须同时依赖 `jackson-annotations` 2.21 |
| `JsonProcessingException` | `JacksonException`（构造器为 `protected`，测试里无法直接 `new`） |
| `canDeserialize` / `canSerialize` | **已移除** → `canRead`/`canWrite` 只判断类型与 mediaType 兼容（同 Spring 7 的 `AbstractJacksonHttpMessageConverter`） |
| `SerializerProvider` | `SerializationContext` |
| `JsonNode.fieldNames()` | `propertyNames()` |
| `ObjectMapper.registerModule(...)` | **已移除**（mapper 不可变）→ `JsonMapper.builder().addModule(...).build()` 或 `mapper.rebuild()` |
| `ser.impl.SimpleBeanPropertyFilter` / `SimpleFilterProvider` | `ser.std.*` |
| `readTree(File)` 抛 `IOException` | 抛 `JacksonException` |

> **行为差异（重要）**：Jackson 3 把 `FAIL_ON_NULL_FOR_PRIMITIVES` 的默认值由 `false` 改为 `true`。
> 框架经 `JacksonMappers.defaultMapper()` **显式关闭**，并集中收拢所有 `new ObjectMapper()`
> ——新增 mapper 构造点时必须走它，否则会漏掉这项兼容。

> **`@JsonFilter` 不受支持**：Spring 7 的 `MappingJacksonValue.getFilters()` 返回的仍是
> Jackson 2 的 `FilterProvider`，与 Jackson 3 的 `ObjectWriter.with(...)` 类型不通，
> 故序列化时**忽略 filters**（`@JsonView` 正常）。

## 4. 依赖图变化（Boot 4 的 starter 精简）

| starter | Boot 3.5 传递 | Boot 4 |
|---|---|---|
| `spring-boot-starter-json` | `spring-web`、Jackson 2 `databind` | **均不再传递**（改用 Jackson 3） |
| `spring-boot-starter-web` | servlet 容器（`tomcat-embed-core`） | **不再传递** → 详见 4.2 |

> 依赖 web 注解（`@RestController`）却只靠 `starter-json` 的模块会**编译失败**，需显式补 `spring-web`。

### 4.1 第三方库版本一律跟随 Boot BOM，不要在本项目钉版

**Boot 4 提升了多项基础库的大版本，钉版会与之相悖**：

| 依赖 | Boot 3.5.16 | **Boot 4.1.0** |
|---|---|---|
| Netty | 4.1.135.Final | **4.2.15.Final** |
| Jackson | 2.x（`com.fasterxml`） | **3.x**（`tools.jackson`，见 §3.4） |

**规则**：`io.netty` 等基础库**不要在根 pom 的 `dependencyManagement` 里写 `<version>`**，
交给已 import 的 `spring-boot-dependencies` BOM（它经 `netty-bom` 覆盖全部所需 artifact）。

**Why**：本分支曾把 14 个 Netty artifact 钉在 `4.1.137.Final`——那是从 master（Boot 3.5
时代）带过来的遗留。它与 Boot 4 BOM 的 4.2.15 冲突，一旦有依赖经 reactor-netty 引入
4.2 的类（如 `MultiThreadIoEventLoopGroup`），同 classpath 上就会 4.1/4.2 混用，
运行期报 `NoClassDefFoundError`。删掉钉版后解析结果全部为 4.2.15，**框架代码零改动**
（4.2 对框架用到的 `ByteBuf`/`ChannelHandler`/`HttpObjectAggregator`/`SslContext.newHandler`
等公开签名均无变化；被删的 `HttpContentCompressor(int,int,CompressionOptions...)` 与
`Http2FrameCodecBuilder.validateRequiredPseudoHeaders` 框架未使用）。

> ⚠️ master 仍用 Netty 4.1（那是 Boot 3.5 的正确基线）。**同步时不要把 master 的
> Netty 钉版带过来**。

### 4.2 无 Servlet 容器带来的行为差异

Boot 4 起 `spring-boot-starter-web` **不再传递 servlet 容器**（如 `tomcat-embed-core`）。
本项目未引入容器，因此：

- **Boot 的 `FilterRegistrationBean<ForwardedHeaderFilter>` 无宿主可挂** → 转发头必须由
  **框架自己解析**（`NettyServerHttpRequest` 的 host/port/prefix + `NettyHttpServletRequest`
  的 `getServerName`/`getServerPort`/`getContextPath`）。不要指望 Boot 的 filter 兜底——
  master 上能工作只是因为那边有容器。
- **`server.servlet.*` 等属性的绑定不会发生**（绑定发生在 servlet 自动配置里）→ 依赖
  「Boot 绑定失败即 fail-fast」的用例在 4.1.x 上不成立，需按条件跳过。

### 4.3 Spring AI：必须用 2.x

Spring AI **1.x 针对 Boot 3**，其 `OpenAiApi` 调用 `HttpHeaders.addAll(MultiValueMap)`，
而该重载在 Spring 7 已改为 `addAll(HttpHeaders)` → 启动即 `NoSuchMethodError`。
**2.x 起与 Boot 4 / Spring Framework 7 对齐**（本项目用 `2.0.1`）。
2.x 经 reactor-netty 需要 Netty 4.2，这也是 §4.1 中「不要钉 Netty 版本」的直接原因之一。

## 5. 测试适配

### 5.1 TestRestTemplate 的统一入口

`TestRestTemplate` / `RestTemplateBuilder` 包名跨版本不同。4.1.x 的
`spring-web-example-support-test` 模块只保留 **`src/main/sb4/java`** 一份薄封装
（专用化后已删除 `sb3` 那套与 profile 切换逻辑），examples 的 E2E 统一
`import io.springperf.example.support.TestRestTemplate`。

> **依赖必须标 `<optional>true</optional>`**：否则 `spring-boot-test` 会经 test-scope
> 把一套 junit 版本传递到下游，与下游自身 `starter-test` 冲突，
> surefire 报 `TestEngine with ID 'junit-jupiter' failed to discover tests`。
> 该 shim 模块无测试，须设 `<skipTests>true</skipTests>`。

### 5.2 已删除的用例

| 场景 | 处理 |
|---|---|
| `ListenableFuture` 返回支持 | **整条链路已删**（adapter / resolver / 端点 / 用例），不再需要 `assumeTrue` 跳过 |
| `@JsonFilter` 序列化 | 框架不支持（见 §3.4），相关用例已删 |

### 5.3 请求体读取：`StringHttpMessageConverter` 必须注册且排在 Jackson 之前

`@RequestBody String` / `HttpEntity<String>` 在 Spring 语义下**始终原样读取**，
即使 `Content-Type` 是 `application/json`——不能落到 Jackson 去按 JSON 解析。

框架经 `HttpBodyCodecRegistry` 把容器里的 `HttpMessageConverter` bean 包装进转换器链，
故 starter 注册了一个 `StringHttpMessageConverter` bean，并让它**排在 Jackson 之前**
（默认 `StringHttpMessageConverter` 没有 `Ordered`，会落到默认优先级、被 Jackson 抢先）。

> ⚠️ **排序必须通过 `Ordered` 接口在实例上表达**：`WebComponentWrapper` 用
> `AnnotationAwareOrderComparator.findOrder(bean)` 读的是**实例**，方法级 `@Order` 无效。

## 7. 常见陷阱

- **不要写版本兼容分支**：本分支专用 Spring Boot 4，直接面向 Spring 7 / Jackson 3 写。
  运行时探测（`isAssignableFrom`、MethodHandle、`Class.forName` 降级）在 4.1.x 上要么恒真要么恒假，
  只会变成死代码或每次请求的额外开销。
- **切换 Spring Boot 版本后必须 `clean`**：跨版本（或从 master 带过来的 `target`）会留下按另一套签名
  编译的字节码，不 clean 会复用它们，报一串 `NoSuchMethodError`
  （如 `HttpEntity.<init>(Object, HttpHeaders)`），**看起来像代码回归、实则是脏 target**。
- **`AutoConfiguration.imports` 要同步**：删除或重命名自动配置类后若忘记改注册项，
  启动时报 `Unable to read meta-data for class ...`，整个 Spring 上下文起不来。
  （改名后尤其注意**重复条目**——`imports` 是纯文本，去重靠人工。）
- **不可变 Builder 不能用继承做 shim**：`RestTemplateBuilder` 每个方法都 `return new ...`；
  继承覆写时 `super.rootUri()` 的返回值被丢弃，链式配置全丢
  （表现为运行期 `IllegalArgumentException: URI with undefined scheme`）。**用组合**。
- **`@Order` 注解在 bean 方法上对框架无效**：`WebComponentWrapper` 读实例的 `Ordered` 接口，
  排序要在**被包装的实例**上表达（见 §5.3）。
- **javadoc 里避免写出 `*/` 序列**：例如 `{@code */*}` 中的 `*/` 会**提前闭合注释块**，
  造成难以定位的语法错误。
- **基础库版本冲突的表现是 `NoClassDefFoundError`，不是编译错误**：本项目曾把 Netty 钉在
  4.1 而 Boot 4 BOM 是 4.2，编译全绿、只在运行某个依赖 4.2 类的模块时炸。**排查手法**：
  `mvn dependency:tree -Dincludes=<groupId>` 看有没有同一 group 的多版本共存（见 §4.1）。
- **不要靠「测试变绿」判断依赖可用**：master 上通过的用例在 4.1.x 失败，可能是它**依赖了
  Boot 的某个能力**（servlet 容器、filter、属性绑定），而 4.1.x 没有。这类失败应改**前提**
  （条件跳过 / 框架自实现），而不是改断言。判定手法：`git worktree add` 出 master 跑同一用例对照。
