# 2.7.x backport 降级适配指南

> 从 master 分支 cherry-pick 代码到 2.7.x 分支时，需要做以下降级适配。
> 2.7.x = Spring Boot 2.7.x + javax + Java 8

---

## 0. 通用原则

### 0.1 不需要 backport 的文件

以下 master-only 文件在 cherry-pick 时**直接跳过**，不进入 2.7.x：

- `WebHttpHeaders.java` — SB 4.x HttpHeaders 兼容层
- `MediaTypeUtils.java` — SB 4.x MediaType 常量桥接
- `ResponseStatusExceptionAdapter.java` — SB 4.x 反射桥接
- `ListenableFutureAdapter.java` — SB 4.x 反射桥接
- `native-image/` 目录下的所有文件 — GraalVM 配置
- `VirtualThreadE2ETest.java` — 虚拟线程测试（需要 JDK 21+）
- `GraalVmNativeImageConfigTest.java` — GraalVM 配置验证

**如果 cherry-pick 引入了对这些文件的引用，需要适配兼容代码**（见各章节说明）。

### 0.2 通用操作逻辑

```
master 代码                                      2.7.x 代码
──────────────────────────────────────────────  ──────────────────────────────
jakarta.servlet.*                          →    javax.servlet.*
jakarta.validation.*                       →    javax.validation.*
jakarta.annotation.*                       →    javax.annotation.*
HttpMethod.valueOf()                       →    HttpMethod.resolve()
Set<HttpMethod>                            →    EnumSet<HttpMethod>
HashSet<>(...) (for HttpMethod)            →    EnumSet.copyOf(...)
HttpMethod.toString()                      →    HttpMethod.name()
getMethod() (代替 getBridgedMethod())       →    getBridgedMethod()（看情况）
HttpStatusCode                             →    HttpStatus
```

|--------|-------|------|

## 4. Spring Framework API 降级

### 4.1 HttpMethod：Interface → Enum

| master | 2.7.x |
|--------|-------|
| `HttpMethod.valueOf(String)` → 回退为 `HttpMethod.resolve(String)` | `MappingRegistry.java` 中调用点 |
| `Set<HttpMethod>` → 回退为 `EnumSet<HttpMethod>` | `HttpMethodMatcher.java`、`HttpBodyCodecRegistry.java` |
| `new HashSet<>(...)` → 回退为 `EnumSet.copyOf(...)` | `MappingRegistry.java` 中创建集合 |
| `HttpMethod.toString()` → 回退为 `HttpMethod.name()` | `HttpMethodMatcher.java` |
| `if-else` 链 → 回退为 `switch(httpMethod)` | `OpenApiAdapter.java` |

### 4.2 getMethod() → getBridgedMethod()

Spring 6 移除了 `getBridgedMethod()`，master 统一使用 `getMethod()`。2.7.x 需要改回。

| 文件 | 修改 |
|------|------|
| `InvokableHandlerMethod.java` | 恢复 `getBridgedMethod()` 覆盖方法 |
| `MappingRegistry.java` | `getMethod()` → `mappingContext.getBridgedMethod()` |
| `ReturnValueResolverRegistry.java` | 恢复 `getBridgedMethod()` |
| `SpringHandlerMethodReturnValueHandlerAdapter.java` | 恢复 `getBridgedMethod()` |
| `OpenApiAdapter.java` | `ctx.getMethod()` → `getBridgedMethod()` |

### 4.3 HttpStatusCode → HttpStatus

| 文件 | 修改 |
|------|------|
| `BaseWebServerHttpResponse.java` | `setStatusCode(HttpStatusCode)` → `setStatusCode(HttpStatus)` |
| `ResponseStatusExceptionResolver.java` | `HttpStatus.resolve(ex.getStatusCode().value())` → `ex.getStatus()` |
| `InvokableHandlerMethod.java` | `getResponseStatus()` 返回 `HttpStatus` 而非 `HttpStatusCode` |

### 4.4 检查清单
- [ ] 全局搜索 `HttpMethod.valueOf(` → 改为 `HttpMethod.resolve(`
- [ ] 全局搜索 `Set<HttpMethod>` → 改为 `EnumSet<HttpMethod>`（确认使用时需要 EnumSet 语义）
- [ ] 全局搜索 `HashSet` 涉及 HttpMethod 的 → 改为 `EnumSet.copyOf`
- [ ] 全局搜索 `.toString()` 涉及 HttpMethod 的 → 评估改为 `.name()`
- [ ] 全局搜索 `if-else` 涉及 HttpMethod 的 → 评估改回 `switch`
- [ ] 全局搜索 `getMethod()` → 评估是否需要改回 `getBridgedMethod()`
- [ ] 恢复 `getBridgedMethod` 的覆盖声明（`InvokableHandlerMethod.java`）
- [ ] 全局搜索 `HttpStatusCode` → 改为 `HttpStatus`
- [ ] 全局搜索 `.getStatusCode()` 在 `ResponseStatusException` 上的调用 → 改回 `.getStatus()`

## 5. AutoConfiguration 回退

### 5.1 spring.factories 恢复

Spring Boot 3.x 使用 `AutoConfiguration.imports`，2.7.x 仍使用 `spring.factories` 的 `EnableAutoConfiguration` 配置。

**操作**：
- 将 `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports` 中的内容**移回** `META-INF/spring.factories` 的 `EnableAutoConfiguration` 条目中
- **删除** `AutoConfiguration.imports` 文件

### 5.2 影响模块

- `spring-boot-starter-web` — AutoConfiguration 类从 `.imports` 移回 `spring.factories`
- `spring-web-websocket` — 同样处理

### 5.3 检查清单
- [ ] 读取 `AutoConfiguration.imports` → 将条目追加到 `spring.factories` 的 `EnableAutoConfiguration` 下
- [ ] 删除 `AutoConfiguration.imports` 文件
- [ ] 保留 `spring.factories` 非 auto-configuration 的条目不变

## 7. 虚拟线程（不需要 backport）

2.7.x 不涉及虚拟线程支持。

## 9. 测试代码适配

### 9.1 常规替换
- 所有 `jakarta.servlet` import → 回退为 `javax.servlet`
- 所有 `jakarta.validation` import → 回退为 `javax.validation`
- 所有 `jakarta.annotation` import → 回退为 `javax.annotation`
- `OpenApiCustomizer` → `OpenApiCustomiser`

### 9.2 API 差异

当 cherry-pick 涉及测试文件时，注意以下常见差异：

| master（JDK 17） | 2.7.x（JDK 8） | 说明 |
|-----------------|----------------|------|
| `request.getInputStream().readAllBytes()` | 改用工具类或自行循环读取 | `readAllBytes()` 是 JDK 9+ API |

| `List.copyOf()` / `Set.of()` | `Collections.unmodifiableList()` / `Collections.singleton()` | 工厂方法多数是 JDK 9+ |
| `TextBlock`（"""） | 改为普通字符串拼接 | TextBlock 是 JDK 13+ |

### 9.3 检查清单
- [ ] 全局搜索并替换 jakarta.* import 在测试代码中 → javax.*

## 10. SB 4.x 兼容层（不需要 backport）

### 10.1 直接跳过的文件

以下文件是 master 上为兼容 SB 4.x（Spring 7.x）而新增的，**绝对不进入 2.7.x**：

| 文件 | 原因 |
|------|------|
| `WebHttpHeaders.java` | SB 4.x HttpHeaders 不继承 Map 的兼容桥接 |

### 10.2 如果 cherry-pick 引入了对这些文件的引用

当 cherry-pick 的代码中引用了上述文件中的内容时，需要针对 2.7.x 做简化处理：

| 引用内容 | 2.7.x 处理方式 |

| `MediaTypeUtils.APPLICATION_STREAM_JSON` | 内联 `new MediaType("application", "stream+json")` |

| `MediaTypeUtils.SPECIFICITY_COMPARATOR` | 直接使用 `MediaType.SPECIFICITY_COMPARATOR`（2.7.x 下存在） |
| `ResponseStatusExceptionAdapter` | 直接调用 `ResponseStatusException.getResponseHeaders()` |
| `ListenableFutureAdapter` | 直接使用 `ListenableFuture`（2.7.x 下存在） |

### 10.3 检查清单
- [ ] cherry-pick 是否引入了上述 master-only 文件？→ **剔除**

## 11. spring-web-view 视图渲染模块 backport

`spring-web-view` 为新模块，backport 涉及 POM、AutoConfiguration 注册、模板引擎 API 三处差异。**最大风险是 Thymeleaf 3.0（SB 2.7）与 3.1（SB 3.2）的 `IWebContext` API 不兼容**。

### 11.1 POM 变更

- parent `pom.xml`：modules 加 `<module>spring-web-view</module>`，dependencyManagement 加 `spring-web-view`
- `spring-boot-starter-web/pom.xml`：加 `spring-web-view`（`provided`）
- `spring-web-test/pom.xml`：加 `spring-web-view`、`spring-web-mvc-support`、`thymeleaf`、`jakarta.servlet-api`→`javax.servlet-api`

### 11.2 Thymeleaf 3.0 vs 3.1 API（核心差异）

| master（Thymeleaf 3.1.2） | 2.7.x（Thymeleaf 3.0.15） |
|---------------------------|---------------------------|
| `IWebContext.getExchange()` → `IWebExchange`（瘦接口） | 无 `IWebExchange`，`IWebContext` 直接有 `getRequest()` / `getResponse()` / `getSession()` / `getServletContext()`（返回 `IThymeleafRequest` 等） |
| `ClassLoaderTemplateResolver` + `setTemplateMode(TemplateMode.HTML)` | `ClassLoaderTemplateResolver` 存在；`TemplateMode.HTML` 在 3.0 为 `SHORTEN_UNIFIED` 演变，需确认 |
| `engine.process(viewName, IContext, Writer)` | 同（3.0 存在） |

**适配**：2.7.x 的 `ThymeleafWebContext` 需改为实现 3.0 版 `IWebContext` 接口（`getRequest`/`getResponse`/`getSession`/`getServletContext`），URL 方言 `@{...}` 由 `StandardLinkBuilder` 直接读取 `getRequest().getApplicationPath()` 等，而非 `transformURL`。实现类可参照 `org.thymeleaf.context.WebContext`（3.0 servlet 版）的结构去 servlet 化。

### 11.3 Spring Framework API 降级

| 文件 | 修改 |
|------|------|
| `ModelSupport.java` | **无需修改**——Spring 5.3 的 `ModelMap implements Model`，`ExtendedModelMap` 兼容性不变 |
| `ModelArgumentResolverProvider.java` | 无需修改 |
| `ThymeleafWebContext.java` | 重写为 3.0 `IWebContext` API（见 11.2） |
| `RedirectView.java` | 无需修改 |

### 11.4 AutoConfiguration 注册

`SpringWebViewAutoConfiguration` 类本身无需改动，但注册方式从 `AutoConfiguration.imports` 移入 `spring.factories`（见第 5 章）。

### 11.5 检查清单
- [ ] query `ThymeleafWebContext` 是否实现 3.0 版 `IWebContext`（`getRequest/getResponse/getSession/getServletContext`）
- [ ] `IWebExchange` / `IWebRequest` / `IWebApplication` 引用是否已清除（3.0 无此类型）
- [ ] 确认 `TemplateMode` 枚举与 `ClassLoaderTemplateResolver` 方法签名兼容
- [ ] `spring-web-view` 加入 parent modules + dependencyManagement
- [ ] `spring-boot-starter-web` / `spring-web-test` POM 依赖更新
- [ ] `SpringWebViewAutoConfiguration` 注册进 `spring.factories`
- [ ] `spring-web-test` 的 `jakarta.servlet-api` → `javax.servlet-api`
- [ ] `ViewRenderTest` 中 `@SpringBootTest(webEnvironment=...)` 的 SB 2.7 兼容性

## 12. Backport 操作流程

每次从 master cherry-pick 代码到 2.7.x 时，按以下顺序执行：

```
□ 0. 确认需要 backport 的 commit 范围
□ 1. 识别本次涉及了哪些变更类别（影响下面需要检查的章节）
     - POM 变更？               → 第 1 章
     - 包路径变更？             → 第 2 章
     - Servlet API 变更？       → 第 3 章
     - Spring API 变更？        → 第 4 章
     - AutoConfiguration 变更？ → 第 5 章
     - GraalVM 相关？           → 第 6 章（跳过）
     - 虚拟线程相关？           → 第 7 章（跳过/注意）
     - Springdoc 变更？         → 第 8 章
     - 测试代码变更？           → 第 9 章
     - SB 4.x 兼容层？          → 第 10 章（跳过+替换引用）
□ 2. 执行 cherry-pick，解决 Git 冲突
□ 3. 按识别出的类别逐项执行降级适配
□ 4. 全局扫描确认无 jakarta.* 残留
□ 5. 全局扫描确认无 JDK 9+ API 残留
□ 6. 全局扫描确认无 master-only 文件/引用残留
□ 7. mvn install -DskipTests 编译通过
□ 8. 运行单元测试
□ 9. 运行集成测试
□ 10. 提交
```
